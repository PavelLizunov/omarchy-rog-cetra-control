   The fabricated defaults and optimistic settings setters are removed. Settings
   are unknown until valid readback, expire after 30 seconds, and invalidate on
   invalid reports/reset/unavailability. Reported all-earbud absence vetoes late
   replies and periodic settings queries. The monotonic scheduler sends verified
   `2b/2c/28/26` round robin, one periodic request every 2500 ms, each field once
   per nominal 10-second cycle at most. The first eligible query is `2b`; retaining
   its deadline across absence/reconnect prevents bursts. UI requests remain

   not a `Date`/wall-clock deadline. Supplied green coverage is 10607 settings

   combined/live evidence. This resolves the original implementation finding
   offline, not the whole P0 section or ASUS hardware-tolerance acceptance.

3. **P1: Freshness is partial, not a general receiver watchdog.**
   Settings and presence/charging observations now expire after 30 seconds;
   the owner disconnects on failed writes but does not expire battery/mode when
   reads stop. The shared service correctly blocks old battery fallback
   after any presence report, but permits it before the first report. Last
   percentages and mode can remain historical indefinitely. Keep BACKLOG P1.7
   open and test a silent receiver that still accepts writes.

4. **P1: Service destruction remains best effort.**
   `CetraService.qml:309-313` signals the detector supervisor but has no awaited
   teardown handshake. `cetra-watch.c:891-896,1011-1017` depends on owner EOF or
   normal termination for cleanup and media-context restoration. The shared
   service avoids per-view ownership churn; it does not prove cleanup across
   hot reload, disable, shell exit, or monitor hotplug. Keep lifecycle acceptance
   under BACKLOG P1.5; do not promise an independent system service.

5. **P2: Telemetry privacy hardened offline; finding partially resolved.**
   Logging is owner-only after election, with an early restrictive umask,
   no-follow opens, owner/regular-file/single-link checks and `fchmod(0600)`.
   An accepted older `0644` log is converted on first owner write, not merely
   by deployment; untouched `.old` backups are not automatically repaired.
   Directory ownership/write-permission checks protect the opened leaf and
   parents used for creation, not every ancestor of an existing path. Unsafe log
   destinations are rejected. Unique `mkostemp` cache replacement is implemented
   too, but does not validate the runtime socket/lock path. Synchronous per-event
   I/O, logging opt-out/policy and parent live permissions/rotation acceptance
   remain under BACKLOG P2.5; the unsafe runtime `/tmp` fallback remains P2.4.

6. **P2: IPC validation/send hardening implemented offline; partially resolved.**
   Non-lighting values now use strict domains and reject trailing arguments.
   LF/CRLF frames reject embedded NUL (discarding the whole frame) and embedded
   CR; malformed frames do not poison subsequent framing. Owner `send_line()`
   handles partial writes and bounded `EINTR` retries, disconnecting on
   backpressure/error rather than queueing delivery. Supplied IPC coverage is
   1464 cases, not rerun here. Mirror forwarding, broader stdout/client
   backpressure and fixed-name `/tmp` fallback remain open under P2.2/P2.4.
   Parent combined/live verification remains pending; this is not global IPC
   or runtime-path closure.

7. **P3: Panel keyboard implementation verified offline, not rendered.**
   Standard panel dispatch now has one shortcut path; focused controls forward
   to it and consume residual events. `collectControls` skips hidden/disabled
   subtrees, traversal visits panel-wide controls, and `focusControl` scrolls
   targets into view. Toggle rows own clicks with non-interactive inner switches;
   hiding the widget closes its popup. Unknown toggles explicitly request On,
   and manual ANC selection disables On/Unknown Adaptive. Supplied coverage is
   21 keyboard fixtures, not a rendered Qt test. Keep live focus order, modifiers,
   alternate layouts, label/switch clicks, hide-while-open, constrained-screen

### Manual RGB

`Cetra.qml:52-68,182-211` separates persisted RGB/theme selection from transport.
Channels are integers `0..255`, defaulting to `255`; theme selection defaults
on (`manifest.json:28-31`). Opening/expanding the palette, changing a slider,
restoring settings, or changing the desktop accent does not call `setLighting`.
Apply and effect buttons are the explicit sending actions
(`Cetra.qml:744-798,948-974`). Apply retains Static/Breathing/Strobing; Off/Cycle/Unknown selects
Static. The preview is a chosen color, not device readback.

`CetraService.qml:166-184` validates normalized channels and does not optimistically
replace the last sent effect. C validation rejects malformed RGB before writing.
The daemon may still replay its previous successfully sent RGB on reconnect in
the same session; saving a new palette selection does not replace that preference
until applied. No automatic hardware theme synchronization is claimed.

### Localization

The widget already calls the integrated `I18n.qml` through `tr()`
(`Cetra.qml:11-18`). `locales/index.json:1-7` registers only English; no actual
translations are bundled or added in this pass. The `locale` setting defaults
to `system`, with explicit `en` available (`manifest.json:24,34-39`).

`I18n.qml:31-64,75-111,156-177` validates modern language tags and safe local
catalog filenames, resolves exact/base/en then call-site English fallback, and
substitutes named placeholders without evaluating values. Register additional
valid language tags with `file`, `name`, and `direction`; the mechanism is not
restricted to two UI languages. It does not claim support for every legacy or
private-only BCP 47 form. RTL metadata drives panel mirroring
(`I18n.qml:13-16`, `Cetra.qml:307-308`); this is scaffolding, not proof of correct
translated layout/focus. Settings-schema labels remain English.

The headset voice selector (`Cetra.qml:998-1024`) is unrelated: verified firmware
options are English, Chinese, and Beeps. Adding UI catalogs cannot expand them.
